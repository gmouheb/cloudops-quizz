# AWS Exam Drill

A practice app for AWS certification exams. It runs in the browser: practice mode with feedback on every answer, and a timed exam mode with a score at the end.

The app is three static files (`index.html`, `styles.css`, `questions.js`) served by nginx in a Docker container.

## Requirements

- [Docker](https://docs.docker.com/get-docker/)

## Run with Docker

Build the image:

```bash
docker build -t aws-exam-drill .
```

Start the container:

```bash
docker run -d --name aws-exam-drill -p 8080:80 --restart unless-stopped aws-exam-drill
```

Open <http://localhost:8080> (or `http://<server-ip>:8080` on a server).

To use another port, change the first number in `-p`, for example `-p 80:80`.

## Deploy a new version

After changing the app, rebuild the image and replace the container:

```bash
docker build -t aws-exam-drill .
docker rm -f aws-exam-drill
docker run -d --name aws-exam-drill -p 8080:80 --restart unless-stopped aws-exam-drill
```

Browsers check for new files on every load, so users get the new version without clearing their cache.

## Useful commands

| What | Command |
| --- | --- |
| See if it is running and healthy | `docker ps` |
| View logs | `docker logs -f aws-exam-drill` |
| Stop | `docker stop aws-exam-drill` |
| Start again | `docker start aws-exam-drill` |
| Remove | `docker rm -f aws-exam-drill` |

## Updating the questions

`questions.js` is generated from the exam markdown files. After editing them, regenerate it and rebuild the image:

```bash
pip install markdown
python3 build.py
docker build -t aws-exam-drill .
```

## Files

| File | Purpose |
| --- | --- |
| `index.html` | The app |
| `styles.css` | Styles |
| `questions.js` | Exam questions, generated by `build.py` |
| `build.py` | Builds `questions.js` from the exam markdown files |
| `Dockerfile` | Builds the nginx image that serves the app |
| `nginx.conf` | nginx settings: caching, compression, security headers |
| `.dockerignore` | Keeps everything except the app files out of the image |

## HTTPS

The container serves plain HTTP on port 80. For HTTPS, put it behind a reverse proxy that handles certificates, such as Caddy, Traefik, or nginx with Let's Encrypt.
